# Repository Guidelines

## Project Overview

`cpp servers` is a KDE Plasma 6 plasmoid (package id `org.kde.cppserver`, v1.8.1, MIT) that configures, starts/stops, and live-tails local C++ inference servers (llama.cpp, strata — via `strata launch --preset` —, audio.cpp, stable-diffusion.cpp, or any custom command) and shows a live per-server/machine stats dashboard. Pure QML + one bash backend script — **no C++ in this repo** despite the name. Form factors: desktop, mediacenter, handset, plus system tray (`X-Plasma-NotificationArea`).

## Architecture & Data Flow

- **QML entry**: `contents/ui/main.qml` — `PlasmoidItem` with all state, the serialized command queue, and polling timers.
- **Backend**: `contents/scripts/cppserverctl.sh` — single bash script, subcommands `init | cfgread | cfgwrite | start | stop | rename | statusall | logread | deps | probe | presets | gpu`. Protocol: stdout is `key=value` lines; errors are `error=<code>` + nonzero exit. Servers run in `setsid` sessions and survive plasmashell restarts. Liveness is derived from `<id>.pid` files (pid + start time, so recycled PIDs are not mistaken for live servers). `rename <old> <new>` migrates `<old>.{log,pid,strata}` to `<new>.{log,pid,strata}`; a running server keeps running (no restart). `deps <binary>...` reports `OK|MISSING` per binary — the UI uses it to flag servers whose executable is not on PATH. `probe <url>` does a short-timeout curl GET of a local http(s) endpoint and prints the raw body (used by the Stats tab). `presets` prints `presets=<json>` from `strata launch --list-presets --output json` (`error=strata_missing|presets_failed`).
- **strata launch semantics**: the template is `strata launch --preset {PRESET} --no-tui` (`{PRESET}` is shell-quoted by `subToken`; preset names may contain spaces — strata slugs them as lowercase non-alnum→`-`). Such cards hide the **Host/Port/Config file** rows (`card.strataLaunch`); the port field stays at 18888 (strata's default) so the monitor can poll it. `strata launch` is a short-lived launcher: `start` extracts the raw preset name (`strata_preset_of`, handles single/double-quoted and bare values) and writes it to a `<id>.strata` marker in `LOG_ROOT`; the already-running guard fires when the pidfile is live **or** strata has a live engine for that slug (`strata_engine_pid`: reads `$XDG_STATE_HOME/strata/runtime/launch-<slug>-*.ready.json`, validates `/proc/<pid>` + cmdline contains "strata"). `statusall` re-points the pidfile at that engine pid and emits `logfile=` pointing at strata's own `$XDG_STATE_HOME/strata/launch/<slug>.engine.log` (a read-only probe dir, so no symlinks out; `logread` whitelists `*.engine.log` under that directory; `logread <path> markers` instead greps the WHOLE file for llama.cpp `loading model` lines — those load lines age out of every tail window and the Stats tab runs this mode once per server run to recover the loaded model name); `stop` runs `strata launch --stop --preset <raw name>` first (marker content, 12 s cap) and only then falls back to SIGTERM-on-process-group; both delete the marker. **External engines**: `statusall` also scans every `launch-<slug>-<hash>.ready.json` in strata's runtime dir and, for each live engine no configured `<id>.pid` claims (claimed-pid set), emits `external-<slug> alive=1 pid= logfile=<engine.log>` + `extport-<slug>=<port>` (from `bound_port`). `main.qml` turns those into read-only `externalServers` entries (`{ id: "external-<slug>", external: true, name: "strata (external <slug>)", command: "strata", host: "127.0.0.1", port: extport||18888 }`) that flow through the same `servers` getter into Servers cards, Logs tail and Stats probes like any strata server; they can only be stopped (`stop external-<slug>` = strata `--stop` + kill; no pidfile/marker ever written), never started/renamed (`error=external_server`) and never land in `servers.json`.
- **UI ↔ script**: no ScriptEngine, no owned processes. All shell traffic goes through `P5Support.DataSource { engine: "executable" }` (import `org.kde.plasma.plasma5support`), which is **single-flight**: `run(cmd, handler)` enqueues; `pump()` fires one at a time; a 20 s watchdog timer unblocks stuck jobs. Duplicate in-flight commands (status/log polls) are dropped. Script is always invoked as `bash <shQuotedAbsolutePath> <subcmd> ...`; absolute path comes from `Qt.resolvedUrl("../scripts/cppserverctl.sh")` in `logic.js`.
- **Config — two distinct systems, do not conflate**:
  1. KConfig (`contents/config/main.xml`): per-widget-instance state in the `General` group — `uiJson` (String, default `{}`, UI state `{activeTab, activeLogId}`) plus log-view settings `logFontAuto` (Bool, default `true`, when on the log follows `Kirigami.Theme.smallFont.pointSize`), `logFontSize` (Int, explicit point-size override used only when `logFontAuto` is off; SpinBox min is 1 so no magic `0`) and `logShowErrors`/`logShowWarnings`/`logShowOom`/`logShowTps` (Bool, default `true`), plus Stats-tab toggles `statShowEvents`/`statShowTps`/`statShowTokens`/`statShowVram`/`statShowHardware` (Bool, default `true`, mirrored as `statShow*` properties in `main.qml` and consumed in the Stats tab of `MainPage.qml`). All applied live; read via `Plasmoid.configuration.*`. The effective size is computed in `main.qml` as the `logFontPointSize` property and consumed in `MainPage.qml` via `page.backend.logFontPointSize`.
  2. Shared server list: `~/.config/cppserver/servers.json` — JSON array of `{ id, name, command, host, port, configFile, preset, enabled }`. Deliberately **not** in KConfig: shared across all widget instances and editable outside Plasma. Written atomically (mktemp + `mv`) with 450 ms debounce (`ConfigServers.qml`), hot-reloaded by the widget: every `statusall` reply carries `cfgmtime=`; on change the widget re-runs `cfgread`.
- **Data flow**: `ConfigServers.qml` edits a `ListModel` → debounced `cfgwrite` → `servers.json` on disk → widget `statusall` → mtime change → `cfgread` → refreshed `ListView`. Command templates use `{HOST}` / `{PORT}` / `{CONFIG_FILE}` / `{PRESET}` placeholders (port `0` drops the port flag; an empty `{PRESET}` drops the `--preset` flag and its value; `~`/`$HOME` expanded). The Preset row (visible only for strata-launch commands, which also hide the Host/Port/Config file rows) is an editable `PlasmaComponents.ComboBox` fed by the `presets` subcommand on load + Reload button. servers.json is its ONLY source of truth: the row never binds `currentIndex`/`editText` — it seeds the text in `Component.onCompleted` and writes back only explicit user input (`onActivated`, or focused typed text that is not explained by the highlighted index), because an editable ComboBox echoes its own C++ bookkeeping through `editTextChanged` (`setCurrentIndex(-1)` clears the text at componentComplete; `rowsInserted` forces index 0 when the preset list lands — either used to save `""`/the first preset into the JSON with the user touching nothing). The strata preset list never auto-writes a value. The `id` (Log ID field) is stable by default but explicitly editable: on change the value is slugified, checked for uniqueness, then `rename <old> <new>` migrates the log/pid files — a running server is not restarted.
- **Logs**: `$XDG_CACHE_HOME/cppserver/logs/<id>.log`, tailed 500 ms while the Logs tab is open (last 400 lines); UI supports substring/regex filter, pause, follow, and a stat summary in the log view's tooltip (error / warning / OOM counts, max/min t/s, plus **current t/s only while it is live** — `logStats` sets `tpsFresh` false once a `stop processing` line closes the last speed line, and the row is gated on the pid being alive) toggleable via the Logs config page. Stats are computed from the visible log text in `logic.js` (`logStats`); t/s is only printed by llama.cpp. Counted lines are highlighted in the log view (`highlightLog`, same classification as `logStats`): OOM/error lines in `Kirigami.Theme.negativeTextColor`, warnings in `Kirigami.Theme.neutralTextColor`, speed (`"N t/s"`) lines in `positiveTextColor` when `logShowTps` is on; the log `TextArea` switches to `TextEdit.RichText` with an HTML span per matched line (lines joined with `<br>`), plain text for placeholders.
- **Stats (Live monitor tab)**: while the tab is open, `pollStats()` in `main.qml` runs `probe <url>` once per second per running server. Endpoint chain: `/health` first (tiny, identifies the server — strata answers `{"service":"strata"}`), then `/metrics` for strata and llama (strata keeps `/metrics` on every later tick; binaries named `llama-server`/`llama-serve` start at `/metrics`). `applyProbe` classifies the reply into `statsMap[id] = { ep, kind, err, health, body, log, at }` with `kind` in `strata` (on `/metrics` there is no `service` key — strata metrics are recognized by `engine`+`history` sections; generic JSON metrics get `json` + `no_metrics`) / `json` / `llama` (Prometheus text; prefix `llamacpp:` upstream, `llm:` legacy) / `none`; llama servers additionally get a 400-line `logread` tail attached (works without `--metrics`): `llamaLogStats` merges the print_timing lines into one record per task id, so requests are BORN at `processing task` and stay live until release — a running task already has its request-stream row: in-tokens from `new prompt … task.n_tokens = P`, live output/speed from the `n_gen = N, tg = A t/s, tg_3s = B t/s` series (tg_3s is llama's own last-3 s rate — the webui's live figure, shown WHILE generating; after release the card holds the final tg, the same number the table's Decode t/s column shows; accepted tokens only: with speculative decoding the eval line's "N tokens per second" also counts rejected drafts, so it is fallback), finish "…" until `stop processing` flips it to stop/length (from `truncated`); ctxUsed while running = prompt + accepted gen, otherwise the LATEST `stop processing: n_tokens` — never the max, a full reprocess erases the old high; prefill progress comes from `prompt processing, n_tokens = R, progress = F` (fills the card's reading-prompt bar + prefill speed); llama.cpp's INFO log carries NO per-request token target, so during decode the card's bar slides as an honest indeterminate block (`slide`: state=generating and no measurable progress) and the row reads `generating %1 tok` from `genNow` — no fake progress fraction; reused tokens = P − prompt-eval tokens; model name from the `loading model '…'` marker, tail first then a whole-log `logread … markers` scan re-run every 30 s while the server runs, so a model hot-swapped without a restart shows up; a marker change also drops `reqSeenMaps` stamps — a swap resets llama's task ids and the old stamps belong to a dead epoch (rows can even read as future clocks)). **llama.cpp reports nothing between requests**, so `parseStats(entry, seen, extra)` keeps a per-server last-good cache (`extra.stick` = `statsStickMaps[id]` in `main.qml`) and every unreported scalar holds its last real value instead of flashing 0/– between ticks; the recovered model is passed via `extra.model` (`statsModels[id]`). Purge-on-stop lifecycle: when a pid dies, `onRunningMapChanged` → `forgetServerStats(id)` drops the `statsMap`/`statsTally` entry, sticky cache, model and `reqSeenMaps` stamps, so Stats cards (gated on `runningMap`) and that server's request rows disappear; a successful start calls `pollStats()` right away instead of waiting a tick. Conversely the **transparent-tick invariant**: a probe that carries no new data never touches `statsMap`. The 404 `/metrics` reply of a no-`--metrics` llama server leaves the entry byte-for-byte intact (no downgrade to `none`, no blank half-tick), and `tailLlamaLog`'s `logread` callback only rebuilds the entry when the log tail actually changed — identical tail means no reassignment, no re-parse, no stream refresh, so the request stream (and with it the card grid, rings and rows) moves only when the log has new content. Entries rebuilt on real changes still seed `log`/`kind` from the previous entry to cross the ~200 ms gap until `logread` lands. The `tailLlamaLog` pump is nevertheless issued on **every** llama probe tick at the top of `applyProbe` — the transparent/dedup `return`s must never gate it: it is llama's only data pump, and one empty or failed read at bootstrap (fresh router log, callback race) would otherwise leave an empty `kind:none` entry stuck forever. `logic.js` renders everything: `parseStats` (per-kind: live state/progress, ctx, vram, counters, `hist` series, `reqs` per-request list, `hardware` incl. `hardware_static`), `parsePrometheus`, `llamaLogStats`, `healthTally`, `serverReqFeed` (one card's table rows: newest first, no-`at` last, capped at `REQ_FEED_MAX`, `fmtReqRow` + token-column masking). `MainPage.qml` draws the unified dashboard: per-server cards (state + phase progress, queue, t/s; on the right a context **GaugeRing** whose `segments` come from `ctxSegs` — prompt/out/otros — and below the name a fixed 5-column token **grid** — petic/req, tok in, tok out, reused, context — with values in `Kirigami.Theme.readOnlyTextFont` so changing numbers never reflow the card), machine KPI tiles (t/s, GPU temp, GPU power, disk, …) that appear only once their source reports data and go stale-blank after 1 s without it (`tileStale`/`tileIds`), plus machine **GaugeRings first** (untitled headline block): CPU (readout `%1 cores / %2 threads`, sparkline from strata's `history`), GPU load (name from `hardware_static`), VRAM (segmented per server process, `fmtMibPair` readout) and RAM, and each card's **OWN request table** (there is NO merged all-servers stream anymore, and the server column is gone — the card IS the server): `main.qml`'s `refreshReqStream` builds `statsFeedMaps` = id → formatted rows (text servers via `serverReqFeed` + `fmtReqRow`, llama log rows stamped on first sight via `reqSeenOf`; audio via `feedRowsOf` — `audioReqs` rows with family + i18n state labels + a non-displayed `err` flag that the State column's `errKey` tints negative), `statShowTokens` masking folded into the row strings and `onStatShowTokensChanged` re-formats without waiting for a probe tick; per-id arrays keep the same reference when their content is identical, and `statsFeedMaps` is only reassigned when at least one feed moved, so idle servers never re-render; `fmtReqRow` prints t/s with `toFixed(2)` — exact measurement, no table rounding. `ReqTable.qml` is generic now: the caller declares the columns ({ key, title, mono, right, errKey }, i18n titles in `MainPage.qml`'s `reqCols`/`audioCols`), the header row is built and measured inside with the data, and `statShowEvents` gates the whole table; each card closes with its table's own footer (`cardFooter`): req total/tok in/tok out/reused% from the session counters for text servers, req total + chunks + wall sums of the shown rows for audio. The footer IS the table's toggle: the table is COLLAPSED by default (`feedOpen` per card delegate, in-memory — the keyed Repeater keeps the choice across probe refreshes), the footer (one-line summary + pan-down/up chevron, a flat checkable `QQC2.ToolButton` with Show/Hide-requests tooltip) stays visible as the card's summary; a collapsed ReqTable has width 0 and falls back to its measured minimums, re-stretching the moment the layout gives it width. **audio.cpp is different on purpose**: it exposes no `/metrics` and its `/health` body is a constant, so its truth is the LOG (`kind: "audio"`, fed by `tailStatsLog`); `audioLogStats` in `logic.js` parses the `[TRACE ts=YYYYMMDD-HHMMSS]` server.model.* block (model/family/task/backend per loaded model — `lazy_load` swaps models per request, so each timing-key PREFIX names a family and rows are family-tagged), the `[SERVER_HTTP_DEBUG] http.headers method=POST path=/v1/audio/…` (request opens; a GET/health never opens one) and the `[TIMING ts=…]` block (per-family `*.session.generate_ms` chunk counts, first-audio marker, un-namespaced `session.wall_ms` closes the request). There is no token or context data for TTS/ASR, and no honest t/s (audio duration ≠ tokens), so audio NEVER feeds the Speed tile, and its card swaps the token grid for an info grid of honest window counters (requests = `st.events` — completed requests counted across the parsed log, same figure the footer prints — plus `audioTot` over the tail feed: chunks = sum, wall = sum, first-audio = mean; chunks/first-audio blanked by `statShowTokens` like every token figure) plus its OWN table (`audioReqs`, cap `AUDIO_FEED_MAX` = 8, newest first, the open request included live while its stamps are < 1 h old so a log replayed after restart can't fake "generating"; columns time/model-family/state/chunks/wall/first-audio via `fmtFeedMs`/`fmtFeedTtfb` — the family is now a COLUMN because `lazy_load` swaps families mid-session and it used to be per-block headers, error rows tinted via the column's `errKey`). Audio technical terms `chunks`/`wall` are NEVER translated anywhere on the card (`Chunks`/`Wall` column titles, info-grid labels, footer — literals, like `Prompt`/`Out`/`Decode t/s`/`Reused`), while first-audio IS (`First audio` → `Primer audio`); every column title starts uppercase. The `gpu` subcommand + `parseGpu` in `logic.js` (result cached as `gpuInfo` in `main.qml`, polled on stats ticks) runs `nvidia-smi --query-compute-apps` and traces every VRAM-holding pid up its parent chain to a live `<id>.pid`, emitting `vramowner=<id>=<MiB>` (`parseGpu`'s `vramBy`: engine children like strata-host/vision attribute to the session that started them; the VRAM ring prefers `hw.byServer`, falling back to the pidfile-pid match, strata's arena and llama's load-log reading), `/proc/meminfo` + `/proc/stat` for RAM/CPU% and `/sys/.../topology/thread_siblings_list` + `nproc` for core/thread counts; the gpu callback injects `tokSample` (live t/s across running servers, ACTIVE-GATED: `refreshReqStream` records per-server `{active, tps}` in `statsLiveMaps` and only GENERATING servers contribute — an idle llama holds its last tg in the sticky cache for the card but contributes 0 to the sample, so the series returns to zero like strata's tok_s instead of plateauing forever) which `pushHist` records as the `tok_s` series — the Speed tile's sparkline for servers that keep no history; the tile's BIG number is the live t/s of GENERATING servers only (0.0 when none generate — the sticky session mean is only ever the subtitle, it never props the number back up). `MainPage.qml`'s `hw` getter merges it with strata's metrics (`pick()`: system value first, strata fallback/complement for name/cores/threads/`hist`). `Donut.qml` (used inside `GaugeRing.qml`) and `Sparkline.qml` are the reusable Canvas widgets (animated `frac`/scales — never jump; flat series, including an all-zero idle window, get the axis bracketed so the line sits mid-height instead of glued to the bottom edge where it read as a missing sparkline). GaugeRing needs an explicit `implicitHeight` next to its `ringSize`: inside a RowLayout an unset height makes `implicitWidth` collapse to the 8 px minimum. Repeaters are keyed by stable ids (`rowIds`/`tileIds`) so 1 s updates never recreate delegates. Cards respect the `statShow*` kcfg toggles. GaugeRing center text prints `<1%` for tiny-but-real fills (llama: 636 of a 131k context). `ReqTable.qml` delegates set `color: Kirigami.Theme.textColor` — a plain `Text` item does not inherit the Plasma palette and would paint black-on-dark.
- **Polling cadence**: status every 2 s expanded / 5 s collapsed; logs 500 ms; stats 1 s but only while the Stats tab is open.

- `contents/config/` — `main.xml` (kcfg schema) + `config.qml` (dialog model with three categories, Servers + Logs + Stats; their `source: "config/…"` paths resolve to `contents/ui/config/…`).

- `contents/locale/` — **generated** compiled translations; regenerated by `translate/build.sh`, do not edit by hand.

## Development Commands

Run from repo root. No sudo, ever (scripts refuse root).

```bash
bash install.sh [--no-restart]        # user-level install: translation build + clean reinstall via kpackagetool6 + qmlcache wipe + plasmashell restart
bash uninstall.sh [--no-restart]      # removes applet; deliberately leaves running servers, logs, ~/.config/cppserver/ untouched
bash make-plasmoid.sh [out.plasmoid]  # zip-based packaging → org.kde.cppserver.plasmoid (requires zip; no plasmoidpackage)
node --test tests/logic.test.mjs     # logic.js regression suite (pure helpers; no Plasma needed)
plasmoidviewer -a .                   # dev: preview without install or restart
LANGUAGE=es plasmoidviewer -a .       # test translations
```

## i18n Pipeline

All user-visible QML text uses `i18n()`/`i18np()` (never concatenate fragments; `--add-comments=i18n` is used, so a `// i18n` comment marks extractable strings):

```bash
bash translate/merge.sh               # after changing user-visible strings: xgettext → po/template.pot, msgmerge all po/*.po
bash translate/new-language.sh <lang>  # scaffolds po/<lang>.po from the .pot (fails if it exists)
bash translate/build.sh               # msgfmt → contents/locale/... + rewrites metadata.json Name[lang]/Description[lang]
```

`merge.sh` and `build.sh` need gettext (`xgettext`, `msgmerge`, `msginit`, `msgfmt`) + `python3`; `build.sh` soft-skips (exit 0) when `msgfmt` is missing. Workflow: new language → `new-language.sh <lang>` → edit `po/<lang>.po` (Lokalize/Poedit) → `bash install.sh`.

## Code Conventions & Common Patterns

- **Never spawn a process from QML directly** — go through the `P5Support` queue (`run(cmd, handler)`) so calls serialize and watchdog-protected.
- **Script stdout is the API**: emit `key=value` lines only; parsers live in `logic.js` (`parseKv`, `parseStatusall`). New subcommands must be parseable there and handled in `main.qml`/`ConfigServers.qml`.
- **Shell injection**: always `shQuote` (from `logic.js`) for any value passed to the script; the script itself is called with an absolute path.
- **Config page saves are debounced** and also flushed on `Component.onDestruction` — keep that invariant when editing `ConfigServers.qml`.
- **JSON is never trusted**: parse via `Logic.safeJsonParse`; normalize via `Logic.normalizeServers` (unique-slug ids, port clamp 0–65535, `enabled !== false`).
- `metadata.json` localized keys (`Name[…]`/`Description[…]`) are **generated** — hand-edit only the base English `Name`/`Description`; `build.sh` rewrites the rest.
- `KPlugin.Version` in `metadata.json` is set by the release workflow from its `version` input (see below); bump it locally before triggering a release. `install.sh` verifies the installed version after install.

## Testing & QA

**`tests/logic.test.mjs` covers the pure half of the Stats tab** (`logic.js`) with `node --test tests/logic.test.mjs` — zero deps, node ≥18. `tests/load-logic.mjs` loads the `.pragma library` by stripping the pragma and evaluating it in a function scope, then asserts the exported surface (which keeps `logic.js` dependency-free — no `Qt.*` at load time). Fixtures are verbatim live-log lines (print_timing aligned columns, speculative decoding) and a strata `/metrics` payload; new Stats regressions MUST add a case there. No lint configs exist (no meson/pyproject/qmllint config); the only workflow is `.github/workflows/release.yml` (release automation, not CI checks). The rest of verification is manual:

- `plasmoidviewer -a .` for UI iteration (no restart); `bash install.sh` for real-environment checks.
- Shell backend can be exercised directly: `bash contents/scripts/cppserverctl.sh <subcommand> [args]` — output is `key=value`, so it's grep/diff-able.
- Translation sanity: `msgfmt --statistics po/<lang>.po` (printed by `merge.sh`); check for fuzzy/untranslated.
- `install.sh` prints installed version and warns if stale-file markers (e.g. `logFilter`) remain in the installed copy.

## Runtime/Tooling Preferences

- Plasma 6 environment (API min 6.0); tooling is `kpackagetool6`, `systemctl --user` (`plasma-plasmashell.service`) or `kquitapp6`/`kstart` for restarts.
- Packaging = plain `zip` of `metadata.json` + `contents/`; install target `~/.local/share/plasma/plasmoids/org.kde.cppserver`.
- No `plasmoidpackage`, no l10n-sqlite, no build system, no package manager.
